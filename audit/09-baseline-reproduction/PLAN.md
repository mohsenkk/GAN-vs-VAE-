## Stage 09 scope and native-driver boundary

**PAPER:** DCGAN-DTA publishes the final 128/4/8 configuration, while its README exposes an 18-point search. A fixed published configuration answers the minimum credibility question; the 18-point search answers the larger, optional model-selection question. Co-VAE publishes the 2 × 2 × 2 grid and training-only fivefold selection but does **not** publish a winning combination for Davis, KIBA, new-drug, or new-target. Targeted full-paper verification reached: **selection procedure found, winner not disclosed**. No fixed grid point can be called the paper's selected or best configuration.

**REPOSITORY:** The DCGAN driver constructs a fresh GAN-backed DTA model for every configuration/fold/pass. Its released two-pass flow repeats the search with the test set as the second-pass stopping set and reports the maximum test CI. The Co-VAE driver passes its repeated outer test fold in place of constructed validation folds, evaluates it during training, and has a result-indexing error: the write pointer advances outside the λ loop, whereas selection advances inside it. These facts explain why minimum Stage 09 must use the native model/training/evaluation components with an explicitly bounded external protocol, rather than claim that a direct invocation of either full released driver reproduces clean train/validation/test separation. No baseline source edit is planned.

**INFERENCE:** One native-dataset run per method tests full-training feasibility and produces a reference result. It does not reproduce the historical search, reported cross-split mean, or numerical paper result. A successful run earns a scoped credibility claim only, even if its metric happens to be close to a paper number.

## Minimum 09A — DCGAN-DTA Variant C, PDBbind warm setting 1

1. **Fixed published configuration:** Variant C; 128 filters; drug kernel 4; protein kernel 8; PDBbind is_log=0; maximum SMILES/sequence lengths 200/2000; batch 256; Adam learning rate .001; maximum 300 epochs. Follow the repository's validation-CI early stopping behavior (mode max, patience 75, best validation weights). This is a fixed paper configuration, **not** an 18-point search.
2. **One representative shipped validation fold:** use the first shipped training fold as validation (836 pairs), the other four as training (3,344 pairs), and the separate fixed 834-pair held-out test set only after model selection. Keep shipped membership and data transformations. Do not run the other four validation folds in minimum Stage 09A.
3. **Bounded 09A preflight:** on that fold and 128/4/8 configuration, perform one native drug-GAN pretraining call and **one** DTA epoch plus native validation, with a resource safety limit. This checks the previously untested protein kernel 8 on the T4 and whether the full setting can be attempted. Do not inspect the test set or interpret its one-epoch metrics as quality. If it fails or exceeds a safety limit, stop and document the boundary before redesigning anything.
4. **09A full, only after preflight passes:** start a separate run on the same fold/configuration, with **one fresh native drug-GAN pretraining call**. Do not reuse preflight GAN weights. Train the DTA model until native validation early stopping or epoch 300, retain the best **validation** checkpoint, and evaluate that selected checkpoint **once** on the untouched held-out test set. No protein GAN is used by Variant C. The full unit is one DTA fit, not five folds.
5. **Evidence to retain:** dataset and shipped-fold hashes; source and runner identity; environment and seeds; GAN/DTA configuration and weights; validation history, selected epoch, stopping reason, full test prediction vector, native CI/MSE/AUPR (threshold y>7)/RM2, timing, memory, and failures. Distinguish the native Keras batch-averaged CI from any separately computed global CI. The paper's Fig. 3 C values (.768/.787/.451/1.907 for CI/AUPR/RM2/MSE) are contextual references, not a pass threshold. Record TF/tf_keras compatibility adaptations and any unmeasured protocol differences.

The paper's seed, test aggregation, and precise stopping rule are under-specified. The repository's full driver has test-informed second-pass selection; this minimum protocol deliberately uses validation for stopping and a single final test. Call it a **full training/evaluation run with the paper-reported Variant C configuration under a named PDBbind protocol**, not a reproduction of Fig. 3.

## Minimum 09B — Co-VAE, Davis new-drug

1. **Native setting and split:** Davis, problem_type=2 (new-drug), the first deterministic runtime six-way drug split from Python split seed **1000**. Use folds 0–4 together for training and fold 5 as the untouched test. Do not use shipped pair-wise folds or ten outer splits. Stage 04 estimated about 25,194 training and 4,862 test pairs; verify exact indices, counts, drug separation, and cross-Python split hashes before execution. Stage 08.5B verified pair-wise hashes only, not these new-drug hashes.
2. **Predeclared representative paper-grid point:** base filters **32**, SMILES kernel **5**, target kernel **7**, and λ setting **−5**. Fix this before any training or test inspection. All three chosen values are in Table 1's stated candidate sets; the two smaller candidate kernels make a simple deterministic representative choice, and −5 matches the released CLI's intended default value. Pass −5 explicitly because the CLI default is a scalar despite nargs='+' and breaks the full driver. In released training, −5 is consumed as the exponent in 10**lamda; the paper does not state that exponent convention.
3. **Static construction check for 5/7/−5:** the released net accepts the two kernels directly. Its decoder input dimensions remain positive: 85 − 3×(5−1) = 73 for Davis SMILES and 1200 − 3×(7−1) = 1182 for targets. Three matching transposed convolutions restore 85 and 1200 positions. Odd-kernel encoder padding preserves their lengths. The λ value is used in loss arithmetic, not model shape. This is **static structural evidence**, not an executed 5/7/−5 forward pass or a memory guarantee. The authors' winner remains unknown.
4. **One complete fit:** use source-native model initialization, loss, RE.train, and native RE.test under a controlled external one-fit protocol. Davis caps 85/1200; embedding 128; batch 256; Adam default learning rate .001; **100 full epochs** on the outer training pool. Retain the native per-epoch optimizer recreation and architecture. Do not run 8×5 CV, a grid sweep, five final fits, or the released driver's repeated-test checkpoint selection. No test-driven early stop: evaluate the outer test **once after epoch 100**. Save final-state weights and predictions with a unique output location so the native fixed checkpoint name cannot overwrite another artifact.
5. **Reported metrics:** record native CI, MSE, RM2 and AUC returned by RE.test when defined, and compute **MAE externally from saved predictions** if available. Do not substitute AUC or AUPR for MAE. Report test membership, actual epoch/update count, finite-loss checks, environment and RNG controls/deviations, runtime/memory, failure/stopping reason, and artifact hashes. The paper's Davis new-drug Table 2 mean±SD (.712±.063 CI, .724±.096 MSE, .550±.048 MAE, RM2 .107) is descriptive context, not a single-split success threshold.

Label the outcome **Co-VAE representative paper-grid full-training reference on Davis new-drug split 1**. It is not a reproduction of the unpublished paper-selected hyperparameters, the ten-split Table 2 mean, or the paper's fivefold selection. The source uses .2 dropout in encoder CNN blocks and .1 in regression layers; paper Table 1 gives .2. Other architecture/objective differences in Stage 03 remain declared. Python 3.12/PyTorch 2.10/T4 and the externally applied set-sampling compatibility shim differ from the historical/local environment and require provenance. Co-VAE's split seed does not by itself control NumPy, PyTorch, DataLoader, CUDA noise, or GPU determinism; record any additional fixed seeds as deliberate run controls, not claims about the paper.

## Claims and completion rule

A minimum run passes its **execution** boundary only if its named full schedule/stopping rule finishes, the specified held-out evaluation succeeds, and predictions, metrics, and provenance are saved. Numerical comparison to a published figure is a separate question requiring aligned estimators, split, selection and aggregation. Missing/failed boundaries must be reported as such, without silently substituting a different configuration.

After successful minimum Stage 09, it is defensible to state:

- **DCGAN-DTA:** a full Variant C training/evaluation run with the paper-reported 128/4/8 configuration completed under the named PDBbind warm setting-1 fold-0 protocol.
- **Co-VAE:** a full training/evaluation run with the predeclared 5/7/−5 paper-grid point completed under the named Davis new-drug split-1 protocol.

Stage 09 alone does **not** establish exact numerical reproduction, all paper averages, Co-VAE's undisclosed selected hyperparameters, reproduction of either original selection process, superiority of one baseline, or hybrid benefit. Matching a paper number by chance would not remove protocol differences. Source behavior, runtime observation, and interpretation remain separate in result reporting.

## Stage 10 and hybrid-oriented roadmap — no execution authorized here

**Stage 09:** native-method credibility on PDBbind for DCGAN-DTA and Davis for Co-VAE. These are different datasets and cannot supply paired samples or a fair direct ranking.

**Stage 10:** the primary comparison is a common **Davis** benchmark for DCGAN-DTA versus Co-VAE. Before execution, define the same drug–target pairs, affinity labels and transformation, train/validation/test membership, evaluation samples, metric implementation, and random split definition for both. Keep GAN versus VAE representation learning, architecture, losses, native optimization strategy, and method-specific hyperparameters distinct. Harmonize the data and scoring protocol, not the models. Stage 10 requires a later explicit design and authorization.

**Stage 11:** extract and align z_GAN and z_VAE representations for the **same underlying drugs, targets, pairs, labels, and split**. Native PDBbind and Davis Stage 09 representations must never be fused as though they describe matched samples.

**Stage 12:** establish a simple hybrid reference, such as fixed fusion or concatenation where shape and sample alignment permit. **Stage 13:** derive/test an optimization- or convex-formulation fusion coefficient. **Stage 14:** ablation and robustness. **Stage 15:** final experiments and thesis tables. These are roadmap intentions only; no fusion, new loss, source change, or later-stage experiment is authorized by this plan.
